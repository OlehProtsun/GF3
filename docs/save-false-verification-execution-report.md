`normalizeGraphSlots` now produces a sorted multiset of day, start, end, employee and status. Storage row IDs and replacement-assigned `slotNo` are technical identity, not schedule content. Every row remains in the comparison, so free capacity and duplicate assigned rows are counted. Existing time/status aliases remain supported. Status is not forced from ownership, and duplicate assignments are not silently removed: unexpected statuses, lost capacity, extra rows and invalid duplicate assignments must remain detectable. The backend also rejects duplicate assigned intervals before its deduplication step.

Consequently the existing checkpoint confirmation path now recognizes a normalized, acknowledged commit, clears its guards, updates the baseline/cache, advances verified progress and continues the remaining graphs. No new write retry or checkpoint bypass was added.

Development/test diagnostics record graph ID and phase, distinguish verified content, semantic mismatch, preflight conflict, API/429 error, readback failure and partial write, and include normalized mismatch records or counts. Graph text is represented only by its field name. Diagnostics do not log names, credentials, notes or cell text, and the normal verification diagnostic work is development-only.
